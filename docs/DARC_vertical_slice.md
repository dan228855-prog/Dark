# D.A.R.C. — вертикальный срез: Выезд №1 (объединённая версия)

Решение автора от 01.10.2026: **сначала вертикальный срез, в него — по максимуму, потом уровни 1–7.**
Срез объединяет обе версии первого выезда:
- **«Первая работа»** (мастер-документ v0.6, раздел 112) — основа маршрута и сюжетные детали;
- **«Плановое списание»** (`DARC_vyezd_1_design.md`) — электросистема, альтернативный путь, ошибка с предохранителем.

Аномалии из всех источников входят, **но не все в одно прохождение**: «главная» гарантирована, остальные — варианты через RareEventManager. Так соблюдаются правила мастер-документа: «первая аномалия маленькая и спорная», «максимум одно сильное событие на уровень», «события не обязательны каждый запуск».

Длительность — ориентир 20–30 минут. Если на тестах выезд не влезает, первыми режем необязательные ветки (отмечены ☆).

---

## Маршрут

КПП (охранник) → проходная → админблок → служебный коридор → рабочая комната → серверный сектор (+ техпомещение рядом) → обратно к выходу → КПП → база.

Фиксированы: вход, охранник, рабочая станция, серверный сектор, электрощит, финальная аномалия, выход.
Процедурно (позже, этап P2): второстепенные комнаты, длина коридоров, где лежат подсказка, интерфейсный модуль, запасной предохранитель и генератор.

## Сцены по порядку

### 1. База — задание
Терминал D.A.R.C., сухой текст: «Восстановить архив с сервера объекта до его планового списания». Без лица, без объяснений.

### 2. КПП
Вечер, лес, туман, старая спутниковая тарелка, часть окон тёмная. Охранник — уставший обычный сотрудник.
- Реплика: «Опять новые работники?» (субтитры, String Table).
- Выдаёт **карту доступа**. На обратной стороне — служебная маркировка, из которой берутся **4 цифры кода**.

### 3. Рабочая комната — доступ к каталогу
- Компьютер требует 4-значный код. Код — на карте (учит: обычные рабочие предметы несут информацию).
- В каталоге: странный «повреждённый вывод» из слов ВСЕ / НЕ / ТАК / ПРОСТО в перепутанном порядке + служебный файл «данные необходимо проверить перед передачей».
- Каталог сообщает: носитель — в серверном секторе, **сервер обесточен** (готовится к списанию).

### 4. Серверный сектор — два независимых препятствия
- **Дверь** заперта: открывается картой доступа или кодовой панелью.
- **Питание** — два пути (несколько решений):
  - **Путь А — щит.** Открыть щиток, правильно: рубильник ВЫКЛ → вставить предохранитель → рубильник ВКЛ.
  - **Путь Б — генератор.** В соседней кладовой переносной генератор. Тяжёлый: в коопе тащат вдвоём, в соло — последовательная процедура (толкать/катить по частям). Подключить к вводу сервера напрямую, в обход щита.

### 5. Ошибка → новая проблема
Если вставить предохранитель при включённом рубильнике — он **сгорает и выбивает соседний контур**: гаснет свет во всём коридоре, которым пришли.
- Появляется внезапная задача «Восстановить свет в коридоре» (не обязательная — можно идти назад с фонариками).
- Решение: запасной предохранитель в шкафу рядом **или** генератор (тогда щит больше не трогают).

### 6. Тяжёлый сервер ☆ (из «Первой работы»)
Стойку нужно перекатить к рабочей точке. Кооп — несколько игроков вместе, при резком движении отсоединяется кабель, нужно закрепить заново. Соло — упрощённая последовательная процедура.
Это единственный большой физический объект уровня (генератор — альтернатива, а не обязательный второй). Если на тестах выезд длинный — убираем эту сцену первой.

### 7. Передача данных
- «EXTERNAL STORAGE NOT READY» → нужен интерфейсный модуль из соседнего техпомещения (короткий путь, не через полкарты).
- «TRANSFER READY» → прогресс 12 / 27 / 46 / 71 / 93 → **пауза на 94%** → «CHECKING DATA...» → «TRANSFER COMPLETE».
- Носитель — физический предмет (`CarryableItem`). Извлечь, нести к выходу. Если несущий погиб — носитель падает (`ForceDrop`), его поднимает другой.

### 8. Обратный путь и финал
- Охранник: «Закончили?» → передают данные → «Хорошо.» → пауза → «Тогда возвращайтесь.» Без музыки.
- Отходя, можно заметить: одно тёмное окно верхнего этажа теперь светится. Не объясняется.

### 9. База — последствия
- Куратор: «Получили?» — «Да.» — «Хорошо.» — пауза — «Следующее задание получите позже.»
- Если в архиве был лишний файл — D.A.R.C. сам упоминает его дежурной фразой, хотя игроки не докладывали.
- Если был блэкаут — в следующем брифинге мельком «плановое обслуживание сети».
- Архив открывает первое улучшение базы: **архивный терминал**.
- Базовый коридор: комната отдыха, терминал, закрытая дверь со светом под ней, динамики, котёнок.

## Аномалии среза

| Аномалия | Источник | Как работает в срезе |
|---|---|---|
| Свет в соседнем коридоре моргнул + шум динамика во время передачи | мастер-документ | **Всегда** (скриптом во время передачи). Списывается на старое оборудование |
| Лишний файл в архиве (не в описи) | «Плановое списание» | **Всегда.** Можно забрать или нет → факт кампании `Slice.ExtraFileTaken` |
| Сигнал из отключённого динамика | мастер-документ | Вариант (редкое событие): Морзе «БЕГИ ПОКА ЕСТЬ ВОЗМОЖНОСТЬ» (основной) / обрывок «…беги…» / щелчок / радиосигнал |
| Исчезающая комната (дверь закрыта, карта не открывает, потом шкаф стоит иначе) | мастер-документ | Вариант (редкое событие), не мешает задаче |
| Физическая аномалия: предмет слегка левитирует / геометрия «не та» | `CLAUDE.md` | Вариант (редкое событие), едва заметное: кружка на столе висит в сантиметре над поверхностью, пока на неё не смотрят |
| Свет в тёмном окне при отъезде | мастер-документ | **Всегда**, без объяснения |

За один проход: 3 «всегда» (все мелкие и объяснимые) + обычно 0–1 вариант. Сильных событий в срезе нет (`bAllowStrongRareEvents = false`).

## Дерево задач (ассет `DA_Mission_Slice`, тип `DarcMissionDefinition`)

`LevelIndex = 1`, `bAllowStrongRareEvents = false`. Тексты задач — строки String Table.

| TaskId | Родитель | Правило | Предпосылки | Обяз. | Кто закрывает |
|---|---|---|---|---|---|
| `GetAccessCard` | — | Manual | — | да | охранник выдал карту |
| `OpenCatalog` | — | Manual | `GetAccessCard` | да | терминал рабочей комнаты: код верный |
| `EnterServerRoom` | — | AnyChild | `OpenCatalog` | да | — |
| ↳ `ServerDoorCard` | `EnterServerRoom` | Manual | — | да | считыватель карты |
| ↳ `ServerDoorKeypad` | `EnterServerRoom` | Manual | — | да | кодовая панель |
| `PowerServer` | — | AnyChild | `OpenCatalog` | да | — |
| ↳ `PowerViaPanel` | `PowerServer` | Manual | — | да | контур `Server` запитан от щита |
| ↳ `PowerViaGenerator` | `PowerServer` | Manual | — | да | ввод сервера запитан от генератора |
| `ConnectInterface` | — | Manual | `EnterServerRoom`, `PowerServer` | да | интерфейсный модуль вставлен |
| `CopyArchive` | — | Manual | `ConnectInterface` | да | передача дошла до 100% |
| `TakeDrive` | — | Manual | `CopyArchive` | да | носитель извлечён |
| `DeliverDrive` | — | Manual | `TakeDrive` | да | носитель передан охраннику |
| `TakeExtraFile` ☆ | — | Manual | `CopyArchive` | нет, скрыта до активации | игрок скопировал лишний файл |

Внезапная задача (добавляет щиток при ошибке): `RestoreCorridorLight`, не обязательная, ничего не блокирует; закрывается, когда контур `Corridor` снова запитан.

Порядок «доступ → питание» не жёсткий: если игроки сначала подняли питание, задача засчитается сразу, как откроется («мир важнее списка»).
