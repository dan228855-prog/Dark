# WorldMemory, RareEventManager и Task System: что сделано и как включить

> **Сначала — `docs/PC_SETUP.md`.** Срез теперь собирается и настраивается без ручной работы в редакторе: серый уровень, интерфейс, управление и данные делает код и скрипт `Tools/darc_setup.py`. Этот файл — справочник по системам, если захочешь собрать свой уровень руками.

Код написан по ТЗ `docs/PROMPT_dlya_silnoy_modeli.txt` и документу «Редкие события» v1.1.
**Код ещё ни разу не компилировался:** в облачной среде нет Unreal Engine. Первая сборка у тебя может выдать ошибки, присылай лог целиком, я исправлю.

## Что появилось в `Source/DARK/`

| Файл | Что это |
|---|---|
| `DarcWorldMemorySubsystem` | Память мира: двери, перемещённые предметы, комнаты, кто где стоит, найденные объекты, взаимодействия, порядок задач, случившиеся события. Только сервер. |
| `DarcRoomVolume` | Коробка «это комната X», по одной на помещение. По ней память знает, кто в какой комнате. |
| `DarcRareEventTypes.h` | Структура строки таблицы редких событий и все её поля. |
| `DarcRareEventAnchor` | Точка в уровне, где событие может «сыграть»: терминал, фото, динамик. Подача (текст, звук, свет) делается в Blueprint. |
| `RareEventManagerComponent` | Сервер решает, случится ли событие, где и для кого, и рассылает клиентам только результат. |
| `DarcTaskTypes.h` | Описание задачи и ассет выезда (`DarcMissionDefinition`). |
| `TaskManagerComponent` | Задачи выезда: цепочки, несколько путей решения, внезапные задачи, связь с фазой выезда. |

Изменены:
- **`InteractableDoor`, `CarryableItem`.** Пишут в память мира. Тексты подсказок вынесены из C++ в поля (см. шаг 3). У двери появился `SetDoorOpen` для событий и электрозамков. Предмет теперь реплицирует позицию: раньше после «положить» у разных игроков он мог оказаться в разных местах.
- **`DarcGameState`.** На нём теперь висят `TaskManager` и `RareEventManager`.
- **`DarcPlayerState`.** Добавлена доставка события одному игроку. Исправлено: повторный `SetAlive(false)` больше не считает смерть дважды.

## Почему память — GameInstanceSubsystem, а не GameState

GameState уничтожается при каждой смене карты (база → выезд → база). Последствия же должны проявляться и на базе после возвращения. Поэтому память живёт в GameInstance всю сессию игры. Внутри два слоя:
- **Слой выезда.** Подробно: позиции, комнаты, журнал. Стирается в начале следующего выезда.
- **Слой кампании.** Коротко: «факты кампании» (`AddCampaignFact`), какие события уже были, сводка прошлого выезда. Его потом будет сохранять Save System.

На клиентах память пустая. Решения принимает только хост, клиентам уходит только результат.

## Шаги в редакторе (один раз)

1. **Собрать проект.** Правый клик по `DARK.uproject` → *Generate Visual Studio project files*, потом собрать в Visual Studio (Development Editor). Либо просто открыть проект: UE предложит пересобрать модуль.
2. **Game Mode.** Сейчас в настройках проекта стоит `BP_FirstPersonGameMode` из шаблона, наш `DarcGameMode` нигде не включён. Нужно:
   - создать Blueprint от `DarcGameState` (например `BP_DarcGameState`);
   - создать Blueprint от `DarcGameMode` (`BP_DarcGameMode`);
   - в `BP_DarcGameMode` указать Game State = `BP_DarcGameState`, Pawn = персонаж из шаблона;
   - выставить `BP_DarcGameMode` в *Project Settings → Maps & Modes* или в *World Settings* тестового уровня.
3. **Тексты подсказок.**
   - Импортировать `docs/ST_UI_RU.csv` в Content как String Table: Import → String Table, например `/Game/Localization/ST_UI`.
   - В Blueprint двери заполнить `Prompt Open / Close / Locked`, в Blueprint предмета `Prompt Pick Up / Drop`: у поля текста есть кнопка выбора строки из String Table.
   - ⚠ Как в UE устроены два языка: таблица строк одна (на исходном языке), второй язык делается переводом через *Localization Dashboard*. Две отдельные таблицы RU и EN так не работают. `ST_UI_EN.csv` пригодится как готовый перевод для дашборда.
4. **Комнаты.** В уровне поставить `DarcRoomVolume` на каждое помещение, подогнать размер коробки и вписать `Room Id` (`Checkpoint`, `Corridor`, `ServerRoom`…).
5. **Таблица редких событий.**
   - Создать её: Miscellaneous → Data Table → строка `DarcRareEventRow`, например `DT_RareEvents`.
   - Назначить её в `BP_DarcGameState` → компонент `RareEventManager` → `Event Table`.
6. **Якоря событий.** Создать Blueprint от `DarcRareEventAnchor`, например «терминал».
   - В `Supported Event Types` вписать тип (`Terminal`).
   - В событии `Play Event Locally` сделать показ: текст на экране из String Table, звук.
   - Поставить якорь в уровень и указать `Room Id`.
7. **Задание выезда.** Создать Data Asset → `DarcMissionDefinition`, заполнить список задач (пример ниже).
   - Запуск выезда: на сервере вызвать `Task Manager → Start Mission` (например, из `BP_DarcGameMode`, когда все готовы).
   - Выполнение: игровые объекты на сервере вызывают `Complete Task` (терминал после ввода кода, щит после рубильника).

## Как устроены задачи

- **Цепочка.** Поле `Prerequisites`: «Скопировать архив» требует «Питание подано» и «Доступ к терминалу».
- **Несколько путей.** Родитель с правилом *AnyChild*: «Подать питание» = «Через щит» ИЛИ «Через генератор». Как только сработал один путь, остальные помечаются «не понадобилась».
- **Ошибка → новая проблема.** `Add Emergent Task`. Пример: сгорел предохранитель → задача «Восстановить свет в коридоре» с `Blocks Task Id` = следующий шаг цепочки. Пока проблему не решат, следующий шаг заблокирован. Если проблема повторится, задача откроется заново.
- **Мир важнее списка.** Если игроки сделали что-то раньше, чем задача появилась (подали питание до того, как дошли до сервера), это засчитывается. Повторять не придётся.
- **Конец выезда.** Когда все обязательные задачи верхнего уровня выполнены, фаза становится *Completed*. Провал задачи с `Fails Mission` или вызов `Fail Mission` ставят *Failed*.

## Как устроены редкие события (поля строки таблицы)

ID строки = ID события. Поля по ТЗ:
- **Тип** (`EventType`).
- **Диапазон уровней** (`MinLevel`–`MaxLevel`).
- **Шанс** за одну проверку (`Chance`).
- **Дистанция** от игрока до якоря (`MinDistance`/`MaxDistance`).
- **Условия** (`Conditions`): игроков ≥/≤ N, команда разделена, комната посещена/нет, дверь оставлена открытой, предмет перемещён, найден объект, выполнена задача, факт кампании есть/нет, событие уже было, прошло N секунд, смертей ≥ N.
- **Сила страха** (`FearLevel`).
- **Повторяемость** (`Repeat`).
- **Перенос в кампанию** (`CampaignFactOnFire`).

Дополнительно:
- **Когда проверять** (`Trigger`): периодически, вход в комнату, выход из комнаты, выполнена задача, начало или конец выезда, только вручную.
- **Кто видит** (`Audience`): все, только один, все кроме одного.
- **Эхо** (`EchoAction`): закрыть дверь, оставленную открытой, или слегка сдвинуть ранее перемещённый предмет. Срабатывает только вдали от всех игроков.

Правила документа соблюдает код:
- не больше одного сильного события за выезд, а на выездах с выключенным `Allow Strong Rare Events` сильных нет совсем;
- между любыми событиями минимум 3 минуты (`MinSecondsBetweenEvents`);
- событие никогда ничего не запирает. Если для него нет места, оно просто не случается.

## Электросистема (для среза)

Классы:
- **`DarcFuseBox`.** Щиток одного контура: предохранитель и рубильник. «Электрощит» — несколько щитков рядом.
- **`DarcFuseItem`.** Предохранитель, переносимый предмет.
- **`DarcGenerator`.** Генератор, тяжёлый объект: в коопе его тащат вдвоём, в соло — волоком. Запускается через ввод.
- **`DarcPowerInlet`.** Ввод для генератора в обход щита. Одно действие: «подключить и запустить» или «заглушить и отключить».
- **`DarcPowerConsumer`.** Компонент для ламп, сервера, терминала.
- **`DarcPowerSubsystem`.** Считает сеть, только сервер.

Настройка для выезда:
1. **Лампы коридора.**
   - Добавить компонент `DarcPowerConsumer`, `Circuit Id` = `Corridor`.
   - В Blueprint на событие `On Power Changed` включать и выключать свет.
   - На событие `On Flicker` мигать.
2. **Сервер.** Компонент `DarcPowerConsumer`:
   - `Circuit Id` = `Server`;
   - `Task Id On Mains Power` = `PowerViaPanel`;
   - `Task Id On Generator Power` = `PowerViaGenerator`.
3. **Щиток `Server`.**
   - `Has Fuse` = нет (сервер обесточен), `Breaker On` = да.
   - `Collateral Circuits` = `Corridor`.
   - `Add Task On Blow` = да, `Task On Blow` = `RestoreCorridorLight` (не обязательная).
4. **Щиток `Corridor`.** `Has Fuse` = да, `Breaker On` = да.
5. **Лампы коридора, задача.** `Task Id On Any Power` = `RestoreCorridorLight`.
6. **Предохранители.**
   - Один лежит у щита (основной путь).
   - Запасной — в шкафу рядом.
7. **Генератор и ввод.**
   - Генератор поставить в кладовую.
   - Ввод `DarcPowerInlet` поставить рядом с сервером, `Circuit Id` = `Server`.
   - Длина кабеля 6 м.
8. **Тексты подсказок.** Строки в `ST_UI` уже добавлены: `Fuse_Insert`, `Breaker_On`/`Off`, `Inlet_Connect`/`Disconnect`, `Heavy_Grab`/`Release`/`ReattachCable`.

Что получится в игре:
- **Правильно:** рубильник выкл → вставить → вкл → сервер запитан, задача «через щит» выполнена.
- **Неправильно:** вставить при включённом рубильнике → искры, предохранитель сгорел, свет в коридоре погас, появилась задача «Восстановить свет». Исправить можно запасным предохранителем в щиток `Corridor`.
- **Через генератор:** притащить генератор к серверу (вдвоём или в соло волоком), подключить на вводе → генератор запускается, сервер запитан, задача «через генератор». Путь через щит станет «не понадобился».
- **Для аномалий:** `Power → Flicker Circuit("Corridor")` моргает светом у всех игроков.

## Терминал, слоты, передача данных, тяжёлые объекты

### Терминал (`DarcTerminal`)
- Код доступа: по умолчанию это код выезда по ключу `CatalogCode` — 4 цифры, одинаковые у всех игроков и разные от выезда к выезду. Карта доступа показывает тот же код: в её Blueprint вызвать `Get Mission Code` с ключом `CatalogCode` и вывести на оборот карты как текст. Это число, а не слова, поэтому String Table тут не нужна. Для ручного теста можно вписать `Fixed Code`.
- `Task Id On Unlock` = `OpenCatalog`.
- `Command Tasks`: команда → задача, например `copy_extra` → `TakeExtraFile`.
- Питание: у компонента `Power` указать контур. Пусто — терминал работает всегда.
- Как это работает у игрока:
  1. Игрок нажимает E на терминале и становится его пользователем, остальные видят «Терминал занят».
  2. Срабатывает событие `On User Changed` с `Is Local User` = да — в нём открыть окно ввода (UMG).
  3. Кнопка «ОК» в окне вызывает на персонаже `Interaction Component → Submit Terminal Input` (терминал, текст).
  4. Закрыть окно — `Leave Terminal`. Если игрок отошёл или пропало питание, терминал освобождается сам.
- Экран для всех: события `On Terminal State Changed` (нет питания / требует код / открыт) и `On Input Result` (верно / неверно). Тексты экрана — строки `Screen_*` в `ST_UI`.

### Слот (`DarcItemSlot`)
Гнездо для предмета из рук: интерфейсный модуль, носитель. `Accepted Class` — какой предмет подходит. `Initial Item` — что стоит в слоте с начала. `Task Id On Insert` / `On Remove` — задачи при вставке и извлечении.

### Станция передачи (`DarcDataTransferStation`)
- Поставить у сервера. Указать `Interface Slot` (модуль) и `Drive Slot` (носитель с архивом стоит там с начала).
- Компонент `Power` по умолчанию на контуре `Server`.
- `Task Id On Complete` = `CopyArchive`. У слота носителя `Task Id On Remove` = `TakeDrive`, у слота модуля `Task Id On Insert` = `ConnectInterface`.
- Экран: событие `On Transfer State Changed` (состояние, процент). Порядок: NO POWER → EXTERNAL STORAGE NOT READY → TRANSFER READY → прогресс → на 94% CHECKING DATA... → TRANSFER COMPLETE.
- Пропало питание во время передачи (например, сгорел предохранитель) — передача встаёт и продолжится сама, когда питание вернут.
- Постоянная аномалия встроена: через 12 с после старта моргает контур `Corridor`. Шум динамика добавить в Blueprint на событие `On Transfer Started Server` или на `On Flicker` у динамика.

### Тяжёлый объект (`DarcHeavyObject`)
- Серверная стойка: Blueprint от `DarcHeavyObject`.
  - Меш в `Body`.
  - `Delivery Target` — пустой актор в рабочей точке.
  - `Task Id On Delivered` — задача доставки.
- В коопе нужно `Required Carriers` (2) игроков, в соло хватает одного, тогда объект тащится медленнее.
- Если тянуть резко или в разные стороны, кабель отсоединяется, все отпускают. Кабель закрепляют повторным E по объекту.
- Генератор — то же самое, но без хрупкого кабеля.

## Готовые данные среза (импорт из CSV)

Таблицы не нужно набивать руками, они лежат в `docs/data/`:

| Файл | Куда импортировать | Тип строки |
|---|---|---|
| `DT_Mission_Slice_Tasks.csv` | DataTable `DT_Mission_Slice_Tasks` | `DarcTaskDefinition` |
| `DT_RareEvents.csv` | DataTable `DT_RareEvents` | `DarcRareEventRow` |

1. **String Table.** Сначала импортировать `ST_UI` по пути **`/Game/Localization/ST_UI`**. Тексты задач в CSV ссылаются на неё через `LOCTABLE(...)` по этому пути. Если String Table лежит в другом месте, найди и замени путь в CSV.
2. **Импорт таблиц.** Перетащить CSV в Content Browser → выбрать *DataTable* и тип строки из таблицы выше.
3. **Ассет выезда.** Создать Data Asset `DA_Mission_Slice` (`DarcMissionDefinition`):
   - `Task Table` = `DT_Mission_Slice_Tasks`;
   - `Level Index` = 1, `Allow Strong Rare Events` = нет;
   - `Campaign Facts On Success` = `Base.ArchiveTerminal`.
4. **Таблица событий.** В `BP_DarcGameState` → `RareEventManager` → `Event Table` = `DT_RareEvents`.
5. **Сцену с тяжёлой стойкой режем?** Удалить строку `MoveServerRack` из таблицы задач.

Что в таблице событий:
- **Срез (уровень 1).** Сигнал из отключённого динамика, четыре варианта, за выезд максимум один: Морзе (основной, самый частый), обрывок голоса, щелчок, радиосигнал. Плюс исчезающая комната, левитирующая кружка (видит только один игрок) и свет в окне при отъезде (всегда).
- **Эхо памяти.** Дверь закрылась, стул сдвинут. Со 2-го уровня.
- **10 событий документа.** С уровней 2–5 по таблице черновика выше.

⚠ Морзе — это звук. Морзе для «БЕГИ ПОКА ЕСТЬ ВОЗМОЖНОСТЬ» и для «RUN WHILE YOU CAN» звучит по-разному, поэтому понадобятся два звуковых файла. UE переключает их по языку через локализацию ассетов в Localization Dashboard.

## NPC, карта доступа, база

### NPC (`DarcNpc`)
Охранник и куратор — один класс без ИИ-поведения. Реплики (`Lines`) — массивы `текст из String Table + пауза перед + длительность`. Субтитры приходят HUD-у через `BP_DarcGameState → On Subtitle` (кто, что, сколько держать). Подписаться в HUD один раз.

- **Охранник КПП:**
  - `Greeting Lines` = `Guard_Greeting`;
  - `Item To Give` = карта доступа (поставить рядом, до выдачи она скрыта), `Task Id On Give` = `GetAccessCard`, `Give Lines` = `Guard_GiveCard`;
  - `Accepted Class` = класс носителя, `Before Receive Lines` = `Guard_Finished`;
  - `Receive Lines` = `Guard_Good` → (пауза 1.5 с) `Guard_GoBack`, `Task Id On Receive` = `DeliverDrive`.
- **Куратор на базе:**
  - `Accepted Class` = носитель, `Receive Lines` = `Curator_GotIt` → `Curator_Good` → (пауза 2 с) `Curator_NextLater`;
  - `Idle Lines` = `Curator_OldSite`;
  - в событии `On Item Received`: если есть факт `Slice.ExtraFileTaken` → `Say Lines` с `Curator_ExtraFile`.

### Карта доступа и двери
- **Карта.** Blueprint от `CarryableItem`. На обороте вывести `Get Mission Code("CatalogCode")`.
- **Дверь серверной.** `Is Locked` = да.
- **Считыватель (`DarcCardReader`) у двери.**
  - `Accepted Class` = карта;
  - `Door To Unlock` = дверь серверной;
  - `Task Id On Access` = `ServerDoorCard`.
- **Кодовая панель.** Это `DarcTerminal` без питания:
  - `Code Key` = свой ключ, например `ServerDoorCode`;
  - `Door To Unlock` = дверь серверной;
  - `Task Id On Unlock` = `ServerDoorKeypad`.
  - Где взять код — решаешь в уровне: записка, надпись на стене, подсказка в каталоге.
- **Запертую дверь можно «дёрнуть».** Будет звук в событии `On Locked Attempt`.

### База (`DarcBaseUnlock`)
- Поставить у части базы, которая открывается по прогрессу.
- `Required Fact` — какой факт её открывает. Архивный терминал открывается фактом `Base.ArchiveTerminal`: его выдаёт успешный срез.
- Показ — в событии `On Unlock State Changed`. Можно указать дверь, которую отпирает.

### «Дух» (`DarcSpiritCharacter`)
- Гибель: опасность на сервере вызывает `BP_DarcGameMode → Kill Player` (контроллер, причина).
- После гибели:
  - предмет из рук падает;
  - тело остаётся, рэгдолл делается в событии `On Player Died`;
  - игрок становится невидимым летающим духом.
- Ввод духа: создать Blueprint от `DarcSpiritCharacter` и привязать клавиши к `Try Flicker`, `Try Toggle Breaker`, `Try Push`. Указать этот Blueprint в `BP_DarcGameMode → Spirit Class`.
- Сила духа растёт со смертями за кампанию и номером уровня: перезарядка короче, толчок сильнее.

## Что проверить после сборки (критерии готовности)

1. Соло: запустить выезд, выполнить задачи по цепочке, фаза доходит до *Completed*.
2. Два игрока (*Play → Number of Players 2, Listen Server*):
   - клиент открывает дверь, хост видит то же самое;
   - клиент кладёт предмет, у обоих он лежит в одном месте;
   - список задач одинаков у обоих.
3. Временно поставить `Chance Multiplier` = 100 и `Min Seconds Between Events` = 5. События должны срабатывать, событие «только один» — видеть только один игрок.
4. Открыть дверь, уйти далеко. Строка с эхом `CloseDoorLeftOpen` закрывает её, у обоих она закрыта.

## Известные ограничения (на потом)

- `DeathCount` живёт в PlayerState и сбросится при смене карты. Для эскалации по смертям его нужно будет переносить: Seamless Travel или Save System.
- Процедурный генератор (этап P2) должен задавать `Memory Id` дверям и предметам явно: имена заспавненных актёров нестабильны.
- Сохранение кампании на диск — Save System (P1). Сейчас слой кампании живёт до выхода из игры.
