# План разработки игры: от идеи до релиза в Steam
## Бюджетная версия — минимальные затраты, соло-разработчик + AI

Основа: MASTER DESIGN DOCUMENT v0.6 и MASTER TECHNICAL BASELINE (UE5, Listen Server, 1–5 игроков, вертикальный срез → полная игра). Этот план разбивает всё на подэтапы, указывает нужные навыки и бесплатные/дешёвые инструменты на каждом шаге.

---

## 0. Общий принцип бюджета

Цель — дойти до релиза в Steam, потратив реальные деньги только там, где без этого физически нельзя обойтись.

**Обязательное требование к игре:** минимум два языка интерфейса и текста — русский и английский. Это заложено в архитектуру с самого начала (весь текст идёт через систему локализации, а не хардкодится), чтобы не переделывать UI и контент задним числом.

**Неизбежные расходы:**
- Steam Direct fee — **$100** (единоразово, за одну игру, возвращается после первых $1000 продаж).
- Возможная регистрация как ИП/самозанятый для получения выплат от Steam — стоимость зависит от юрисдикции, обычно небольшая или нулевая (самозанятость в РФ — бесплатно).

**Всё остальное — бесплатно или почти бесплатно при должном выборе инструментов** (см. раздел 4).

## 2. Этап 0 — Подготовка (до первой строчки кода)

**Что сделать:**
1. Установить Unreal Engine 5 (бесплатно, Epic Games Launcher).
2. Создать приватный репозиторий на GitHub (бесплатно) + Git LFS для крупных файлов (бесплатный лимит есть, при превышении — минимальная доплата, обычно не нужна на этой стадии).
3. Настроить структуру проекта в UE5 под будущие Core Systems (папки Characters, Core, Network, UI, Levels_Test и т.д.).
4. Завести отдельный документ-трекер задач (можно бесплатно: Trello, Notion free tier, GitHub Projects).
5. Зафиксировать соглашение: MASTER TECHNICAL BASELINE — источник истины для технических решений.

**Стоимость:** 0.
**Навыки, нужные уже здесь:** базовый Git, базовая навигация в UE5.

## 3. Этап 1 — Вертикальный срез

Цель этапа (по документу): доказать жизнеспособность цикла на одной маленькой локации, без финального контента.

### 1.1 Базовый Player и камера
- Player Character, Player Controller, базовое движение и камера (от третьего лица, т.к. кооператив и физическое взаимодействие).
- **Навыки:** C++ (базовый класс персонажа) + Blueprints (настройка ввода).
- **Стоимость:** 0 (встроенные системы UE5 Enhanced Input — бесплатны).

### 1.2 Сетевой фундамент
- Game Mode, Game State, Player State.
- Listen Server как первая реализация (сервер = один из клиентов).
- Подключение двух клиентов для теста.
- **Навыки:** C++ (Replication, RPC), понимание Client-Server модели UE5.
- **Стоимость:** 0. Для локального теста двух клиентов деньги не нужны — тестировать можно на одном ПК (два инстанса игры) или по локальной сети/Steam Remote Play. Полноценный интернет-тест — через бесплатный Steam Relay (после подключения Steamworks SDK) или обычный проброс порта.

### 1.3 Interaction System
- Универсальная система взаимодействия с объектами (не «нажми E на кнопке», а осмысленное взаимодействие).
- **Навыки:** C++ (интерфейсы, компоненты) + Blueprints (конкретные интерактивные объекты).

### 1.4 Task / Objective System (минимальная версия)
- Одна простая задача D.A.R.C. (например: «найти пароль → подключить накопитель → скопировать данные»).
- **Навыки:** C++ (базовая система состояний задачи) + Blueprints (конкретная логика).

### 1.5 Item / Carry System
- Один переносимый объект (накопитель/флешка) с серверной синхронизацией состояния (кто держит, где лежит).
- **Навыки:** C++ (репликация владения объектом).

### 1.6 Дверь с реплицируемым состоянием
- Открыта/закрыта, синхронно видно всем игрокам.
- **Навыки:** Blueprints + базовая репликация переменных.

### 1.7 Терминал/компьютер
- Простой интерфейс для ввода пароля/получения данных.
- **Навыки:** UMG (UI) + Blueprints.

### 1.8 Минимальная физика
- Классификация объектов: A — серверная физика, B — серверное интерактивное состояние, C — локальный визуал.
- Одна простая физическая проблема (например, нужно сдвинуть предмет, чтобы пройти).
- **Навыки:** физика UE5 (Physics Constraints, Chaos), понимание сетевой физики.

### 1.9 Одна аномалия
- Минимальный пример «системы аномалий» — то, что позже станет полноценной Anomaly System.
- **Навыки:** Blueprints, немного C++ для встраивания в общую архитектуру.

### 1.10 Завершение сессии
- Корректный выход из локации, завершение задачи, разрыв/сохранение сессии.

### 1.11 Локализационный фундамент (RU + EN)
- Уже на срезе весь текст (терминал, задачи, UI) выводится через String Tables UE5, а не хардкодится в Blueprints/C++.
- Заведены две локали: ru и en, переключение проверено на срезе.
- **Навыки:** UE5 Localization Dashboard, String Tables.
- **Стоимость:** 0 — встроенный инструмент движка. Если разработчик не носитель английского — черновой перевод можно делать самостоятельно + бесплатные инструменты (DeepL, Google Translate) с последующей вычиткой носителем-волонтёром (например, через инди-девелоперские Discord-сообщества) или самостоятельной вычиткой.

### Ассеты для вертикального среза
- Только placeholder-геометрия: встроенные примитивы UE5 (кубы, цилиндры) или бесплатные модульные наборы из Fab (бывший Marketplace) — там регулярно есть бесплатные пакеты (Quixel Megascans входит в UE5 бесплатно).
- Звук: несколько бесплатных SFX с freesound.org (лицензия CC0) для двери, терминала, шагов.

**Итоговая стоимость этапа 1:** 0.

### Критерий готовности (Acceptance Criteria) этапа 1
«Два клиента подключены к Listen Server. Игрок 1 открывает дверь. Игрок 2 видит то же состояние двери. Один переносимый объект синхронно реплицируется. Задача D.A.R.C. выполняется от начала до конца в соло и в коопе. После повторного входа состояние не расходится с серверным.»

## 4. Этап 2 — P1: доработка систем поверх среза

Цель: превратить работающий срез в устойчивую платформу для контента.

- **UI/UX** — полноценные меню, HUD задач. Навыки: UMG. Стоимость: 0.
- **Звук** — базовая аудиосистема (Metasounds), больше SFX. Источники: freesound.org, OpenGameArt.org (много CC0/CC-BY), звуки из бесплатных UE5 audio packs.
- **Анимации** — базовый набор анимаций персонажа. Бесплатно: Mixamo (бесплатные анимации и риггинг, интеграция с UE5 через плагин), UE5 Manny/Quinn skeleton (входит в движок бесплатно).
- **Save/Load** — система сохранения кампании (нужна по документу: Save/Progression System). Навыки: C++ (SaveGame классы UE5, встроены бесплатно).
- **Asset pipeline** — процесс: placeholder → модульный → уникальный ассет, без блокировки программирования. Стоимость: 0, если использовать бесплатные модульные наборы Fab/Megascans на этом этапе, финальные уникальные ассеты откладываются на этап 6.

**Стоимость этапа 2:** 0.

## 5. Этап 3 — Процедурная генерация

- Room-based генератор на заранее проверенных комнатах и соединениях.
- Требования: гарантированная достижимость целей, отсутствие softlock, seed для воспроизводимости.
- **Навыки:** C++ (алгоритмы генерации графа комнат), Level Design (модульные комнаты, которые стыкуются между собой).
- **Стоимость:** 0, если комнаты строятся из тех же бесплатных модульных наборов, что и в срезе.

**Риск (по документу, из раздела ревью):** повторяемость технических задач между уровнями — контролируется дизайном, не деньгами.

## 6. Этап 4 — Контент уровней 1–7 (первая сюжетная арка)

- Покомнатная детализация каждого уровня, с проверкой каждого обязательного действия в соло и коопе.
- Внедрение трёх классов аномалий (A — физические, уровень 4; B — информационные, уровень 5; C — реактивные, уровень 6; объединение — уровень 7).
- Четвёртая стена полноценно накрывает на уровне 5, контакт становится личным на уровне 6, ИИ физически присутствует на уровне 7.
- Весь новый текст (диалоги, записки, задачи D.A.R.C., подсказки) сразу заводится в String Tables на русском и английском — никакого текста "на потом без локализации".
- **Навыки:** Level Design, нарративный дизайн (Narrative/Event System), балансировка сложности задач, ведение локализационных таблиц.
- **Ассеты:** здесь уже стоит начать закладывать часть уникальных моделей (по документу — не блокируют программирование, но нужны к финальному контенту). Бесплатные источники: Fab marketplace (сезонные бесплатные паки), Sketchfab (модели с CC-лицензиями, проверять разрешение на коммерческое использование), собственное моделирование в Blender (полностью бесплатный редактор) при наличии навыка или готовности его освоить.
- Если совсем нет навыка 3D-моделирования и нет времени учиться — можно оставаться на модульных бесплатных наборах даже для релиза (многие успешные инди-игры выходят на переиспользуемых ассетах).

**Возможная минимальная статья расходов:** если бесплатных ассетов не хватит на нужную уникальность атмосферы — недорогие паки на Fab/itch.io (обычно $5–20 за пак), но это не обязательно.

## 7. Этап 5 — Кооп-полировка и валидация

- Проверка паритета соло/кооп (любая механика, требующая нескольких игроков, обязана иметь альтернативу для одного).
- Стресс-тест репликации (двери, задачи, переносимые объекты, аномалии, сюжетные события).
- **Навыки:** QA-тестирование, сетевой дебаг (профилировщик UE5, встроен бесплатно).
- **Тестировщики:** бесплатно — друзья/сообщество (Discord-сервера инди-разработчиков часто помогают тестировать бесплатно за фидбэк/взаимный тест их игр).

## 8. Этап 6 — Финальный арт/аудио пайплайн

- Замена части placeholder/модульных ассетов на уникальные там, где это критично для атмосферы (по документу — не всё обязано быть уникальным).
- Финализация Narrative/Event System, Audio Event hooks.
- **Стоимость:** зависит от того, сколько уникальных ассетов решено делать. Минимальный бюджет — 0 (полностью модульно-переиспользуемый арт), реалистичный минимальный бюджет с точечными уникальными ассетами для ключевых сюжетных объектов — от $0 до нескольких десятков долларов.

## 9. Этап 7 — Steam-интеграция и подготовка к релизу

- Регистрация как Steam-партнёр (нужен Steam Direct fee **$100**, возвращается после первых $1000 выручки).
- Интеграция Steamworks SDK: базовый онлайн (Steam Sessions вместо/поверх голого Listen Server для матчмейкинга через Steam), достижения (опционально), облачные сохранения (опционально).
- Оформление страницы в Steam: скриншоты, трейлер, описание — можно сделать самостоятельно бесплатно (запись геймплея через встроенный OBS Studio, бесплатный).
- **Навыки:** работа со Steamworks SDK и Steamworks Partner backend.
- **Стоимость:** $100 (единственная обязательная статья расходов во всём плане).

## 10. Этап 8 — Предрелизная стабилизация и бесплатный маркетинг

- Закрытые тесты (Steam Playtest — бесплатная функция Steamworks).
- Сбор фидбэка, багфиксы, оптимизация.
- **Маркетинг без бюджета:**
  - Страница в Steam с вишлистом — публикуется бесплатно за 1+ год до релиза.
  - Devlog-посты в Reddit (r/IndieDev, r/gamedev), Twitter/X, itch.io.
  - Демоверсия на бесплатных ивентах (Steam Next Fest — бесплатное участие для подходящих демо).
  - Видео/стримы через контакт с мелкими стримерами (бесплатные ключи в обмен на освещение).
- **Стоимость:** 0, при условии, что маркетинг строится на органическом охвате, а не на платной рекламе.

## 14. Что реально может потребовать денег (риски бюджета "около нуля")

- Git LFS сверх бесплатного лимита при большом объёме бинарных файлов (модели, текстуры) — обычно доплата небольшая ($5/мес за доп. пакет на GitHub).
- Если совсем не хватит бесплатных ассетов под нужную атмосферу — точечные покупки на Fab/itch.io ($5–20 за пак).
- Локализация RU+EN обязательна и заложена с нулевым бюджетом (самоперевод + бесплатные инструменты). Дополнительные языки сверх этих двух — уже опциональны и не входят в базовый план.
- Если качество английского текста от самоперевода окажется недостаточным для релиза, может понадобиться платная вычитка носителем — это единственный реалистичный сценарий, где локализация выйдет за рамки $0.
- Юридическое оформление получения выплат от Steam — зависит от страны, в РФ статус самозанятого бесплатен, но нужно проверить актуальные условия приёма платежей Steam для конкретной юрисдикции на момент релиза.

Все эти пункты — не обязательны для выхода в релиз, только опциональные улучшения.
